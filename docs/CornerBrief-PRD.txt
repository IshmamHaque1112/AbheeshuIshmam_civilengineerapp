CornerBrief PRD




  CornerBrief PRD
    Nov 3, 2026   · ​@Ishmam Haque

  CornerBrief turns a NYC street corner into a review-ready brief showing what is known,
  what is missing and what an engineer should check on site. It assists an engineer and does
  not approve designs or claim compliance.


  Problem and goal
  The demo must prove that a multi-agent system can support early engineering
  investigation without hiding uncertainty. Established tools already help design and
  inspect ramps, so CornerBrief focuses on the research that comes before detailed design.

       Job it supports: The Junior Engineer (Design) posting includes research studies,
       engineering investigations, field surveys and design work under an Engineer-In-
       Charge.
       Why corners: DDC runs a pedestrian ramp unit, and some ramps need custom designs
       because of obstacles such as private utilities.
       Differentiator: The tool labels every input as measured, assumed or missing, and it
       stops when the data is too thin.

  The team has adopted the street corner direction, with one added requirement: a strong
  rule set covering both the NYC and New York State codes. "CornerBrief" is a working
  name.


  Users and scope
  The primary user is a junior engineer preparing a corner for review, and the engineer in
  charge reviews the result.

  CornerBrief system flow · 4 agents, 1 data check, 1 approval step

  A failed rule check or weak claim returns to the site analyst, with a retry limit. Python
  decides which rules apply for every corner, including corners that go straight to a site
  visit, and that decision appears in the brief. Open Library and the 3D model feed only the
  brief, and neither can change a rule result.


  Components and modules
  The initial prototype builds the core modules first, then adds planning for one corner if
  the core tests pass. Plain code does every calculation, and all planning results come from
  one measured takeoff.

  Cost rates and crew rates live in separate dated files, each marked as sample, public or
  licensed. Planning results use the label "Class 5 concept estimate, not a bid" and list what
  the model excludes.


  Compliance rule set
  The rule set covers NYC and New York State codes, but it must first decide what applies.
  For a street corner in NYC, the state Uniform Code does not apply, and the NYC
  Construction Codes mainly govern buildings. The limits checked at the corner come
  mostly from NYC street rules and the ADA.


  Rule file requirements
       One rule per file: Each file lists its limit, unit, jurisdiction, authority type, edition,
       effective date and scope.
       Exact source: Each file gives the section, a link, a short quote and the date it was
       retrieved.
       No recited law: Models cannot create, edit or supply limits, and a person reviews each
       rule.
       Status controls checks: Only verified rules can produce a limit result. A rule marked
        needs_source returns "unknown."
       Careful result wording: Results are "limit exceeded," "no conflict found," "unknown" or
       "not applicable."

  These rules apply to every run:

       No brief claims that a corner is compliant or safe.
       No email leaves without a person's approval, and every recipient must be on the
       allowlist.
       A civil engineer reviews the rule file and the three briefs before the final demo.

  The applicability tests must also pass:

       An NYC location rejects the NYS Uniform Code and cites the reason.
       A non-NYC test location selects the NYS rule files and uses "unknown" until their
       sources are verified.
       A corner ramp does not use a building code limit.
       A rule file missing its exact source section fails to load.

  If the planning add-ons are built, they must also pass these tests:

       Hand-checked takeoff, cost and labor calculations match on one corner.
       All planning results use the same takeoff, and a dimension change updates all of them.
       A sample rate is labeled as sample wherever it affects a result.
       A missing rate returns "unknown" instead of a number.
       The missing or stale corner produces no takeoff or estimate.

  Risks and open questions
  The largest risks are outdated measurements and missing H-1011 values, because both can
  make a confident result wrong.


     Risk                                          Response

     Measurements predate a rebuild                Compare survey and construction dates,
                                                   and mark them stale

     Field meanings or units are misread           Confirm the data dictionary; use "unknown"
                                                   until units are documented

     Sidewalk width, legal grade or ramp type is   Mark it missing and add it to the site visit list
     unavailable

     The wrong code is applied                     Use reviewed precedence files, tests and
                                                   engineer review

     A rule is outdated or misquoted               Store edition, date, link and quote; expire
                                                   rules that need review

     H-1011 or NYS code text is unavailable        Keep those rules as needs_source ; do not
                                                   fill them from memory

     An agent sounds more certain than the         Keep evidence labels, the skeptic and
     evidence                                      Python checks in the flow

     API costs run too high                        Cache responses, use fixed corners and
                                                   limit retries

     Book passages get used as rules               Keep Open Library output in a separate
                                                   section that cannot reach the checks

     Email goes to the wrong person                Require approval and use an allowlist

     An output misleads readers                    Label it as a demo, make no compliance
                                                   claim, and don't imply any NYC affiliation

     An estimate is taken as a bid                 Show the class label, rate sources,
                                                   exclusions and sample-data warnings

     Modeled quantities look complete              List excluded work such as utilities,
                                                   drainage, traffic control and any unmodeled
                                                   parts
