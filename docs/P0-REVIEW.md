## Findings: permission language and tests that do not prove the P0

### 1. High: enabled labels/plans do not require complete rule coverage (R4/R16/R28)

`cornerbrief/orchestrator.py:60–69` defines “verified” as no previews plus at least one “no conflict found.” It does not require all applicable rules to be verified/resolved, inspect `rules_needing_sources`, or require reviewed precedence. `run_checks` emits unknown outcomes without previews for reference and needs-source rules (`cornerbrief/checker.py:81–104`). Those holes therefore satisfy the label gate.

Manual reproduction using `tests/test_flow.py::fully_reviewed`'s approach (in-memory reviewed copies plus its four corner field entries), `ReplayClient('standard')`, flag on and `save=False`: returned **probably standard and a plan**, while six outcomes remained unknown, including `H1011-SHEETS-2-9`. Replacing the slope rule in memory with a needs-source/no-limit placeholder still returned **probably standard and a plan**. Relevant files: `cornerbrief/orchestrator.py::provisional_label`, `rules/nyc/H1011-SHEETS-2-9.yaml`, `cornerbrief/checker.py::run_checks`. The passing `tests/test_flow.py::test_export_includes_the_plan_only_with_a_label` actually blesses the incomplete-coverage fixture.

The flag is solely an environment boolean, with no stored R28 pass evidence (`cornerbrief/config.py::labels_enabled`). More seriously, `labels_off` is derived from that flag rather than final label eligibility: with it on and ordinary unreviewed rules, a scripted writer returning **“This is probably standard.” / “Proceed with construction.”** was accepted while `run['label']` remained `None` (`cornerbrief/orchestrator.py:102,202`, `cornerbrief/guards.py:17–27`). `tests/test_v3.py::test_writer_label_is_rejected_while_labels_are_off` explicitly accepts the first phrase when `labels_off=False`; it does not prove R4's complete-evidence/review/rules gate for narrative output.

Saved runs also bypass the current feature flag on retrieval/export: `presented` hides options only when a saved label is absent, and does not strip saved labels/plans when the flag turns off; the page renders saved `label_reason` and `planning` directly (`cornerbrief/review_export.py:21–27`, `cornerbrief/app.py::get_run`, `cornerbrief/static/app.js:132,161`). No cited R4 test covers enable → save → disable → reopen/download.

### 2. High: incomplete evidence/review can still produce reassuring output (R3/R4/R6/R18/R20)

Both standard and constrained samples returned CHECKS in manual `save=False` diagnostics with **four missing corner inputs**; standard had **61 unknown rule outcomes**. `data_sufficient` only gates eight `REQUIRED_FIELDS`, and `decide_state` stops only for review status `incomplete`, not `not run` (`cornerbrief/evidence.py:5–13,154–167`, `cornerbrief/orchestrator.py:46–57`). The passing `tests/test_v3.py::test_story_4_missing_evidence_stops_that_check_even_when_the_corner_continues` and `test_rerun_moves_a_stopped_corner_and_reports_changes` demonstrate this intentional divergence from the broad stop-on-incompleteness wording in `docs/PRD.md`.

Skeptic schema validity is weaker than a finished substantive review: `{verdict: 'pass', challenges: [{severity: 'rework', ...}]}` is legal and `analyze` marks it finished solely from the verdict (`cornerbrief/models.py::Challenge`, `SkepticOutput`; `cornerbrief/orchestrator.py:161–174`). Existing malformed/retry tests do not exercise that contradiction (`tests/test_v3.py`, cases 6–7).

Date coverage is similarly narrow: `currency_problem` requires a completion date only when status contains “Constructed,” and `_on_site` marks new values measured when no known rebuild date proves them stale. It does not preserve the missing-date uncertainty. Existing missing-date tests use Constructed records and no site override (`cornerbrief/evidence.py:39–49,69–74`; `tests/test_v3.py::test_r28_1_missing_survey_or_construction_dates`).

Other output that could read as permission:

- **“Within limit if confirmed”** is displayed beside unreviewed previews, and conflict text says measurements fall within the stricter limit despite unreviewed rules (`cornerbrief/static/app.js::previewTag`; `cornerbrief/checker.py::find_conflicts`). Disclaimers help but do not make a supported final result; current source review is zero verified rules (`tests/test_core.py::test_no_rule_is_verified_until_someone_reviews_it`).
- **“before it was accepted”** appears whenever retries are nonzero, including exhausted/incomplete reviews (`cornerbrief/static/app.js:152`; `tests/test_v3.py::test_r28_7_exhausted_retries` does not render this text).
- Agent prose such as **“Proceed with construction.”** contains none of the forbidden words and no unsupported number, so passes `check_text` even with labels off (`cornerbrief/guards.py`). The banned-word parametrization proves five exact phrases, not absence of permission language (`tests/test_flow.py::test_banned_claims_rejected`).
- Rejection diagnostics repeat banned words, e.g. `Uses the banned claim "compliant"`, and the download appends those messages under Rejected agent output. These are quoted diagnostics rather than endorsements, but defeat the literal zero-occurrence packet metric (`cornerbrief/guards.py::check_text`, `cornerbrief/review_export.py::to_markdown`; `tests/test_flow.py::test_brief_writer_claim_falls_back_to_checked_results` only inspects the summary and presence of rejection).
- When enabled, “probably standard,” likely options, concept quantities and work sequence can imply readiness despite the unresolved rule coverage above (`cornerbrief/orchestrator.py::provisional_label`; `cornerbrief/static/app.js::plan`; `cornerbrief/review_export.py::to_markdown`).

### 3. High: browser switching and same-corner reruns lack complete async isolation (R28/R31/R8)

`run(key)` uses a request counter to discard late initial corner responses, which is useful (`cornerbrief/static/app.js:35–46`). However, `wireField` awaits photo reads **before** taking the destination from mutable `current.id` and the date/name from the current DOM. A switch during that await can submit old entries to the newly displayed corner; the request-counter check happens only after the mutation request. Corner-level keys such as `corner:sidewalk_width` are valid for both corners (`cornerbrief/static/app.js:101–115`; `cornerbrief/field.py::validate_entries`). This is a code-path finding, not a browser-executed reproduction.

The release and field handlers share `requestId`, but a field rerun does not increment it. A release response for the original run arriving after a same-corner rerun can restore `current` to the old run and replace its release panel, leaving the newer packet body displayed. The reverse ordering can leave an old release handler operating on a newer `current` (`cornerbrief/static/app.js::wireField`, `wireRelease`). Existing tests call Python concurrently or HTTP sequentially; none executes these browser handlers (`tests/test_v3.py`, case 10; `tests/test_web_and_fetch.py::test_site_measurement_rerun_over_http`).

### 4. Medium: unit validation and change reporting tests are narrower than their requirements (R19/R31)

`validate_rule` requires a `unit` key but never validates its value. Manual reproduction: setting the numeric `ADA-2010-405-2-SLOPE` unit to `None` still passed validation. The downstream checker may return unknown, but malformed rule units should fail loading rather than reach execution (`cornerbrief/rules.py:6–39`, `cornerbrief/checker.py::check_value`). `tests/test_core.py::test_undocumented_unit_returns_unknown` tests measurement documentation, not rule-unit validity.

`compare_runs` compares only label/value/on-site status for input changes and preview-or-result plus math for result changes. Correcting only date, measurer or photo is not reported; an unreviewed preview becoming a final result with the same math is also not reported (`cornerbrief/field.py:96–120`). Existing R31 tests change values/labels and do not prove these transitions. `tests/test_v3.py::test_photo_is_saved_and_attached` checks existence using a PNG signature plus dummy bytes; it does not prove a photo can be decoded/displayed or survive standalone Markdown export (`cornerbrief/field.py::save_photo`; `cornerbrief/review_export.py::to_markdown`).

1. **Close the R4 release gate across all output paths.** Require complete applicable evidence, finished consistent review and verified rule coverage before labels/options/plans or equivalent narrative wording; apply the same gate when reopening/exporting saved runs. Keep `SHOW_LABELS_AND_PLANS` off until expanded R28 tests demonstrate it. Add enabled-flag missing-source/reference/contradictory-review tests and save-on/reopen-off tests. 2. **Make incomplete evidence/review stop consistently and prove browser isolation.** Resolve the CHECKS-with-missing-inputs/no-review behavior against v3; preserve date uncertainty; remove misleading acceptance/permission wording. Capture immutable run IDs and form data before awaits, reject stale mutations before POST, and invalidate pending release callbacks on rerun. Test delayed corner, photo, rerun and release responses in the actual browser flow, with labels enabled as well as disabled. Targets: `cornerbrief/evidence.py::data_sufficient`, `currency_problem`, `_on_site`; `cornerbrief/orchestrator.py::decide_state`; `cornerbrief/static/app.js::wireField`, `wireRelease`; `tests/test_v3.py`, `tests/test_web_and_fetch.py`.
3. **Complete the four-corner demo evidence and honest source-backed check.** Save the actual Thomson Ave corner through the existing fetch workflow, retain unknown live-record limits until dataset units are documented, and obtain named human review for the exact rule/precedence coverage used in the demonstration. Add a four-corner acceptance assertion so absence cannot pass unnoticed. Targets: `scripts/fetch_corners.py`, `data/live/real_test.json` (currently absent), `cornerbrief/data_loader.py::list_corners`, `scripts/review_rule.py`, `rules/precedence/`, `tests/test_flow.py::test_real_test_only_listed_when_saved_and_samples_never_change`.
